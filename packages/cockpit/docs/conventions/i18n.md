# i18n conventions

- No i18n library in a package. The app gives an `I18nAdapter` in the configuration:
  `resolveText(namespace, key, params, defaultValue)`, `currentLocale()`, optional `onChange(listener)`.
  - Without an adapter, the package's English texts are used.
  - How the app looks up a text is its own business (i18next, a plain object, …).
- Never name a specific i18n library in a package's code, docs or specs, except react-i18next as the example.
- The namespace of a package (2026-10-10): its name in camelCase, no prefix: `'dataTable'`, `'fileUpload'`,
  `'formValidation'`.
  - A clash with an app's own namespace is solved in the app's adapter (e.g. ``ns: `components.${namespace}` ``).
- Keys: camelCase, separated by dots (`home.attention.allGood`).
