# i18n conventions

- Tier 1 (see `general.md`): no i18n library in a package. The app gives an `I18nAdapter` in the configuration:
  `resolveText(namespace, key, params, defaultValue)`, `currentLocale()`, optional `onChange(listener)`.
  - Without an adapter, the package's English texts are used.
  - How the app looks up a text is its own business (i18next, a plain object, …).
- Never name a specific i18n library in a package's code, docs or specs, except react-i18next as the example.
- The namespace of a package: its name in camelCase, no prefix: `'dataTable'`, `'fileUpload'`, `'formValidation'`.
  - A clash with an app's own namespace is solved in the app's adapter (e.g. ``ns: `components.${namespace}` ``).
- Keys: camelCase, separated by dots (`home.attention.allGood`).
- Tier 2 (see `general.md`): i18next with react-i18next, the app's instance (`I18nextProvider`).
  - The package's texts (English and German) are i18next resources it exports (e.g. `microAppTexts`), under its
    namespace; the app adds them to its instance: `resources: { en: { microApp: microAppTexts.en }, … }`.
  - The package reads them typed by its own keys, not through the app's declared resource types (i18next's
    `CustomTypeOptions`): an app that types its own resources need not list the package's (`useTexts()` of
    `micro-app`).
